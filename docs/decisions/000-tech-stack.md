# 000 技术栈与数据存储选型

- 状态：已确认
- 日期：2026-11-24

## 背景

系统需要管理个人文档、保存解析文本和分块、支持中文全文检索与语义检索，并调用大模型生成摘要和问答。单人开发和本机演示要求方案能够运行、部署、测试和写入论文，同时避免维护过多数据系统。

## 备选方案

1. SQLite + FTS5 + FAISS：安装轻量，但业务数据与向量索引分离，需要额外处理一致性、映射和备份。
2. PostgreSQL + pgvector：使用一个数据库保存业务数据和向量，支持事务、关系查询和统一备份。
3. PostgreSQL + 独立向量数据库：检索能力更专门，但增加服务部署、数据同步和故障处理成本。

## 决定

前端采用 Vue 3 + TypeScript；后端采用 Python 3.12 + FastAPI + SQLAlchemy/Alembic；数据库采用 PostgreSQL 并启用 pgvector；中文全文检索采用 jieba 预分词；向量模型采用 BGE；生成模型采用 OpenAI 兼容大模型 API。原始文档保存在本地文件目录，不存入数据库 BLOB。

## 后果

- 文档、分块、向量和引用关系可以在同一事务中维护，减少多套存储之间的数据不一致。
- 开发和演示环境需要运行 PostgreSQL，并安装 pgvector 扩展。
- PostgreSQL 自带全文检索不直接解决中文分词，需要在写入和查询前统一进行 jieba 分词。
- 更换向量模型时需要记录模型版本并重建相关向量，不能混用不同维度的向量。
- 备份必须同时覆盖 PostgreSQL 数据库和原始文件目录。
